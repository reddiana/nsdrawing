# ADR-0004: 구조 편집기 (트리 모델 + 자동 레이아웃)

## 배경

NS 차트는 블록 안에 블록이 중첩되는 트리 구조이고, 화살표 없이 위에서 아래로 진행한다. 편집기의 데이터를 "도형과 좌표"로 둘지 "구조"로 둘지 정해야 한다.

## 결정 기준

- 구조적으로 잘못된 차트를 만들 수 없어야 한다. ([[01-requirements#^nfr-integrity]])
- 텍스트를 고치면 크기와 배치가 자동으로 맞춰져야 한다. ([[01-requirements#^lay-autosize]], [[01-requirements#^lay-branch-width]])
- 감싸기, 풀기 같은 구조 편집을 지원해야 한다. ([[01-requirements#^edit-wrap]])
- 코드 변환으로 확장할 수 있어야 한다. ([[01-requirements#3.6 코드 연동]])

## 검토한 대안

### 자유 배치 그림판 (도형 + 좌표)

- 장점: 일반 다이어그램 도구와 같은 조작감
- 단점: 잘못된 구조를 막을 수 없음, 텍스트를 고칠 때마다 손으로 크기 조정, 코드 변환이 어려움

### 구조 편집기 (트리 모델 + 자동 레이아웃)

- 장점: 항상 올바른 구조, 크기·배치 자동, 구조 편집과 코드 변환이 자연스러움
- 단점: 사용자가 위치를 마음대로 조정할 수 없음, 레이아웃 알고리즘을 직접 만들어야 함

## 결정

모델은 **트리**로 두고, 화면 배치는 트리에서 **자동 계산**한다. 사용자는 좌표를 다루지 않는다.
모든 모델 변경은 불변 조건을 지키는 **편집 명령**으로만 한다.

## 결과

- 좋아지는 점: 구조 오류가 원천적으로 차단된다. 레이아웃이 순수 함수라 테스트하기 쉽다.
- 감수하는 점: 블록별 수동 위치·크기 조정은 지원하지 않는다.
- 후속 작업: 노드 타입과 불변 조건 → [[01-model]], 레이아웃 알고리즘 → [[02-layout]]
