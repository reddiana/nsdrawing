# ADR-0001: ADR로 아키텍처 결정을 기록한다

## 배경

요구사항 문서에 "결정이 필요한 사항" 목록으로 결정을 관리해 왔다. 결정이 늘어나면서 근거와 검토한 대안이 요구사항 문서를 채우게 되었고, 나중에 "왜 이렇게 했지?"를 추적하기 어려워졌다.

## 결정 기준

- 결정의 근거와 대안을 나중에도 찾을 수 있어야 한다.
- 요구사항 문서는 "무엇을"에만 집중해야 한다.
- Obsidian에서 읽고 편집하기 편해야 한다.

## 검토한 대안

### 요구사항 문서 안에 결정 섹션 유지

- 장점: 문서 하나로 끝남
- 단점: 문서가 커지고, 결정이 바뀌면 이전 근거가 사라짐

### ADR (결정 1건 = 파일 1개)

- 장점: 결정마다 배경·대안·결과가 남음, 대체 이력 추적 가능
- 단점: 파일 수가 늘어남

## 결정

`docs/adr/`에 ADR을 MADR 형식을 줄인 [[0000-template|템플릿]]으로 기록한다.

- 파일 이름: `NNNN-영어-슬러그.md`, 본문은 한국어
- 상태: 제안됨 → 승인 → 대체됨 / 폐기
- 승인된 ADR은 고치지 않는다. 결정이 바뀌면 새 ADR을 쓰고 `supersedes` / `superseded-by`로 잇는다.
- 목록은 [[00-index#아키텍처 결정 기록 (ADR)]]에서 관리한다.

## 결과

- 좋아지는 점: 요구사항 문서가 간결해지고, 결정 이력이 남는다.
- 감수하는 점: 새 결정마다 파일을 만들고 목록을 갱신해야 한다.
