**세션 시작 요약 (2026-10-10 프로토타입 세션에서 저장)**
- 지난 세션(10-10)에서는 inbox를 모두 처리했고, Obsidian 스파이크로 `.ns.svg`만 편집기로 열 수 있다는 것을 확인했습니다. 지금은 "요구사항 리뷰용 프로토타입" 단계입니다.
- inbox는 비어 있었습니다. 남은 부채는 11건이었습니다. 대부분 Claude가 임시로 정한 규칙이라 확인이 필요한 것들입니다.

**프로토타입:** https://claude.ai/artifact/RuUjpc7YmCcbJXAdCeQiRG (사본 `journal/assets/2026-10-10-ns-prototype.html`)

예제를 하나 띄운 상태로 열립니다. TIM2 인터럽트 처리기이고, 이벤트 머리·If 중첩·강조 영역 두 개·Do-While이 들어 있습니다. 두 강조 영역은 맞붙어 있고 그중 하나는 접혀 있습니다.

들어간 것: 블록 4종, 선택(Shift+클릭 자동 확장, Shift+↑↓), 키보드 이동, 넣기·지우기·글자 고치기, 감싸기·풀기, 되돌리기·다시, 자동 레이아웃, 기본 스타일 C, 접기(제어 블록 "⋯ 블록 n개", 범위는 처음 접을 때 칸 안에서 이름 묻기), 강조 영역(굵은 테두리, 넓히기·합치기, 맞닿으면 따로, 중첩 거절), 이벤트 머리, 블록 글자 예제 두 가지(코드식·문장식), `.ns.svg` 받기·열기와 "SVG 보기".

점검 방법: 프로토타입 오른쪽 패널의 "만들며 생긴 질문" 10개를 봐 주세요. 특히 중요한 것은 셋입니다. (전체 목록: [[2026-10-10-02-prototype#만들며 생긴 질문 (메인테이너의 답을 기다림)]])
1. 펼친 뒤에도 이름 붙은 범위가 보이지 않게 남습니다 (ADR-0017의 결과). "이름 붙은 범위 보기"로 볼 수 있습니다.
2. 기본 이름을 고르면 "이미 물어봤음"을 파일에 남겨야 해서, 이름 없는 범위가 저장됩니다.
3. 강조 영역이 안쪽 깊은 곳에 있을 때 그 바깥을 강조하면, 넓힐 수도 새로 만들 수도 없어 지금은 거절합니다.

써 보시면서 질문 번호로 답해 주시거나 새로 떠오른 요구사항을 말씀해 주세요. 필요하면 프로토타입을 바로 고칩니다.

## 지금 단계

**프로토타입을 써 보는 중.** 2026-10-10에 요구사항 리뷰용 프로토타입을 만들었습니다 → [[2026-10-10-02-prototype]]. 요구사항과 아키텍처 결정(승인 ADR 0001~0008, 0012~0017)을 정리했습니다. 2026-10-09에 Google Drive 연동과 기본 시각 스타일을 더했고, 2026-10-10에 inbox를 모두 처리했습니다(접기, 강조 영역, 이벤트 머리, 공유 URL 등). Obsidian 스파이크로 `.ns.svg` 방식이 된다는 것도 확인했습니다.

앞으로의 큰 순서(메인테이너가 inbox 1-4~1-6에서 밝힌 방향): 요구사항을 최대한 더 모음 → 요구사항 리뷰용 프로토타입 → 아키텍처 설계 → **테스트 설계와 테스트 코드 작성** → 개발 → MVP(첫 출시, [[01-requirements#5. MVP 범위]]). 프로토타입과 아키텍처 시작 시점은 아래와 같이 정했습니다 (2026-10-10).

> [!note] 용어
> **프로토타입**은 요구사항이 맞는지 확인하려고 만들고 버리는 것, **MVP**는 개발을 거쳐 처음 내놓는 제품입니다. → [[spike-prototype-mvp]]

- **요구사항 리뷰용 프로토타입을 만든다. 코드는 버린다.** 남은 기능 후보(Scratch 이벤트, 강조)가 요구사항에 들어간 직후, 아키텍처 설계 전에 만든다.
	- 넣음: 웹 페이지 하나. 블록 4종(처리, If, While, Do-While), 선택·감싸기·풀기·Undo, 자동 레이아웃, 기본 스타일(시안 C), `.ns.svg` 다운로드
	- 더 넣음 (2026-10-10): 접기(처음 접을 때 칸 안에서 이름 묻기), 강조 영역(굵은 테두리, 겹치면 넓히기, 맞닿으면 따로), 이벤트 머리 블록, 블록 글자 예제 두 가지(코드식·문장식. "블록 글자는 코드인가 문장인가"를 보고 정하려고)
	- 뺌: Obsidian, 데스크톱, Drive, 테마, 내보내기, 정확한 텍스트 폭
	- 방법: Claude가 Artifact(웹 페이지 하나)로 만든다. 만들기 1~2세션 + 써 보기 1주
- **아키텍처 설계는 세 조건이 모두 맞으면 시작한다.**
	1. inbox의 기능 후보가 모두 요구사항에 들어가고 우선순위가 붙었다.
	2. 아키텍처를 가르는 열린 질문에 답이 났다: 블록 글자는 코드인가 문장인가, 저장 SVG의 색, 주 사용자, 확장자(스파이크로 `.ns.svg` 확인함).
	3. 프로토타입을 써 본 뒤 나온 새 요구사항이 모델(블록 종류, 트리 구조)과 파일 형식을 바꾸지 않는다.
